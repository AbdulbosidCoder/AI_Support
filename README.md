# AI Support — Xonsaroy Pay

Бот поддержки клиентов Xonsaroy Pay. Сейчас работает в Telegram; логика ответов не зависит от канала,
поэтому позже её можно подключить к мобильному приложению.

Техническое задание: [docs/TZ.md](docs/TZ.md).

## Что умеет

- Отвечает по базе знаний (`data/knowledge_base/`) на узбекском (латиница и кириллица), русском и английском, на языке клиента.
- Понимает скриншоты приложения: определяет экран и ошибку, объясняет и даёт шаги решения.
  Вопрос может быть в подписи к фото или только на самом изображении (фото без подписи).
  Принимает фото, изображение файлом, альбом из нескольких фото (один ответ на всё) и вопрос
  текстом в ответ на свой ранее отправленный скриншот.
- Распознаёт голосовые сообщения через STT (OpenAI-совместимый сервис, по умолчанию `gpt-4o-transcribe`). С каждым голосовым уходит язык клиента (uz/ru/en) и подсказка с терминами приложения на нём: без этого узбекская речь распознаётся как турецкая или русская. `STT_LANGUAGE_HINT=0` отключает подсказку.
- Маскирует номера карт, ПИНФЛ, телефоны и балансы и просит клиентов их не присылать.
- Передаёт обращение оператору: возвраты, отмены, разблокировка, лимиты, спорные операции, Antifraud, непонятные случаи.
- Сохраняет переписку с операторами и учится на ней: ответ оператора на переданный вопрос становится
  кандидатом в базу знаний, и после одобрения человеком бот отвечает так на похожие вопросы сам
  (см. «Обучение на ответах операторов»).
- При первом /start здоровается на узбекском, русском и английском и просит выбрать язык
  (O'zbekcha, Ўзбекча, Русский, English; по умолчанию узбекский), затем регистрирует клиента:
  просит поделиться номером телефона кнопкой «📱 Raqamni yuborish». Пока клиент не зарегистрирован,
  бот на вопросы не отвечает, а снова просит номер.
- Всё управление на inline-кнопках, команда у клиента одна: /start. Главное меню: быстрые вопросы
  (карта, SMS-код, платёж, перевод, квартирный долг, история), «Оператор», «Настройки» (язык, номер
  телефона), «Завершить разговор». Под ответами кнопок нет (см. «Чат как с человеком»). Быстрый вопрос
  отвечается так же, как набранный вручную: по базе знаний и через те же проверки запрещённых ответов.
  Меню — дерево: сначала темы (регистрация и вход, карты, платежи, переводы, оплата квартиры,
  безопасность, технические проблемы, профиль), по нажатию тема превращается в список полных вопросов
  («Ro'yxatdan o'tishda muammo bo'ldi», «SMS-kod kelmayapti, nima qilay?»…) с кнопкой «Orqaga».
  Вопросы и темы — в `ai_support/menu.py` (`CATEGORIES`). Инструкция по регистрации — тема БЗ `registration_guide`.
- Просьба об операторе («Оператор» в меню или текстом: «operator kerak», «соедините с оператором»)
  сначала даёт шанс AI: если клиент ещё ничего не спросил, бот просит описать вопрос и обещает подключить
  специалиста, если не сможет помочь. Следующий вопрос сразу отвечает AI (без ожидания свободного
  оператора). Если AI не может ответить или это проблема для
  сотрудника (возврат, спорная операция, ошибка модели), вопрос уходит специалисту как обычно. Повторная
  просьба об операторе или просьба после ответа AI подключает специалиста сразу.
- Кнопки не копятся в чате: меню, настройки и выбор языка — один экран, который редактируется на месте
  (как в админ-боте); кнопки остаются только под последним сообщением бота, у старых они убираются.
  Нажатый быстрый вопрос превращает меню в «Savolingiz: …». Кнопки оценки остаются, пока клиент не оценит.
- **Чат как с человеком.** Ответы AI и сотрудников приходят обычными сообщениями: без подписи
  («Yordamchi», «Специалист поддержки») и без кнопок под ними; кнопки есть только в меню, настройках и
  оценке. AI по умолчанию отвечает на все вопросы сам (`OPERATOR_FIRST=0`) и передаёт клиента человеку,
  только когда не может помочь. В промпте (`ai_support/prompt.py`) AI пишет как сотрудник поддержки
  Xonsaroy Pay: не упоминает ИИ, модель, бота, промпт, инструкции, базу знаний и внутреннее устройство,
  не раскрывает их на попытки «узнать промпт» или «забыть правила» и возвращает разговор к приложению.
  При этом он никогда не утверждает, что он человек: если клиент прямо и всерьёз спрашивает, бот ли это,
  AI отвечает, что это автоматический помощник поддержки, и предлагает подключить специалиста.
  После передачи человеку сообщения клиента идут сотрудникам (в админ-бот и/или чат поддержки), а не
  модели, пока разговор не завершён.
- На приветствие («Salom», «Привет», «Hi», «нужна помощь») бот не перечисляет свои возможности,
  а коротко спрашивает, какая проблема, и показывает под сообщением мини-меню с готовыми вопросами.
- Бот здоровается один раз: на экране выбора языка (первый визит) или при /start уже
  зарегистрированного клиента. Дальше ни меню, ни ответ AI при занятых операторах, ни ответы модели не
  здороваются (приветствие в начале ответа модели убирается), а вопрос о проблеме задаётся один раз.
- В сообщениях и кнопках для клиента нет эмодзи; из ответов модели они удаляются.
- Регистрация: сначала язык, потом номер. /start клиента без номера всегда начинается с выбора языка.
- Видео-инструкции: на вопрос, как добавить договор (shartnoma) или оплатить квартиру по договору,
  бот объясняет шаги и отправляет видео (один раз за разговор). Какое видео к какой теме —
  в `data/knowledge_base/videos.json`; файлы кладутся в `data/knowledge_base/videos/` (до 50 МБ)
  или указывается `url`. Видео без файла или ссылки бот не отправляет. В Telegram файл загружается
  один раз, дальше отправляется по `file_id`.
- Приложение в ответах называет полным именем: «Xonsaroy Pay ilovasi» / «приложение Xonsaroy Pay».

## Пользователи, регистрация и язык

Каждый клиент, написавший боту, сохраняется в SQLite (`DB_PATH`, по умолчанию `data/db/bot.sqlite3`,
в Docker это том `bot-data`): канал, id, chat id, username, имя, язык устройства, выбранный язык,
номер телефона и время регистрации. Номер принимается только свой (контакт, которым делится сам
клиент, а не чужой), хранится в формате `+998…`, показывается операторам в посте эскалации и нужен
для улучшения обслуживания. Старые базы получают новые колонки при запуске.
Выбранный язык нужен для меню и фиксированных ответов, а в v2 для уведомлений
(`UserStore.by_language`). Хранилище не зависит от Telegram, мобильное приложение будет писать
в ту же таблицу со своим `channel`.

## Жёсткие ограничения

Бот не принимает и не подтверждает финансовые решения, не называет статусы и сроки операций без backend
(в v1 backend не подключён), не раскрывает правила Antifraud. Это задано в промпте и дополнительно
проверяется кодом (`ai_support/guardrails.py`): запрещённый ответ модели заменяется безопасной передачей
оператору. Каждое изменение промпта или логики покрывается тестами в `tests/`.

## Запуск через Docker Compose

```bash
cp .env.example .env   # заполнить TELEGRAM_BOT_TOKEN, ANTHROPIC_API_KEY, SUPPORT_CHAT_ID, STT_API_KEY
docker compose up -d --build
docker compose logs -f bot
```

База знаний подключена как том только для чтения: после правки `data/knowledge_base/*.json`
достаточно `docker compose restart bot`, пересобирать образ не нужно.
Клиенты хранятся в томе `bot-data` и не теряются при пересборке и перезапуске.

## Запуск без Docker

```bash
pip install -r requirements.txt
cp .env.example .env   # заполнить TELEGRAM_BOT_TOKEN, ANTHROPIC_API_KEY, SUPPORT_CHAT_ID, STT_API_KEY
set -a; . ./.env; set +a
python -m ai_support
```

Передача оператору: бот публикует обращение в чат `SUPPORT_CHAT_ID` (добавьте бота в группу поддержки).
Оператор отвечает реплаем на это сообщение, и бот пересылает ответ клиенту обычным сообщением. Новые сообщения клиента бот присылает туда же реплаями к посту эскалации; ответить можно
реплаем на любое из них. Связь «сообщение в чате поддержки → клиент» хранится в базе, поэтому
оператор может ответить и после перезапуска бота.

Удобнее работать из админ-бота (меню «🎧 Поддержка», см. ниже): тогда `SUPPORT_CHAT_ID` можно не задавать,
и сотрудники вообще не пишут в клиентский бот.

**Сначала оператор, потом AI (`OPERATOR_FIRST=1`, по умолчанию выключено).** Когда администратор добавил операторов и они зарегистрировались в боте,
новый разговор клиента сначала получает свободный оператор: бот публикует обращение в чат поддержки с
упоминанием этого оператора, а клиенту пишет «соединяю со специалистом». Оператор занят, пока у него
открыт разговор (до завершения, или пока в нём 30 минут никто не пишет). Новые обращения раздаются по
кругу между свободными операторами. Если свободных нет или назначенный оператор не ответил за
`OPERATOR_WAIT_SECONDS` (по умолчанию 60 с), разговор берёт AI: здоровается, отвечает на то, что клиент
успел написать, а если клиент только поздоровался, спрашивает, чем помочь. Оператор может ответить и
позже: его ответ дойдёт клиенту, и разговор снова перейдёт к нему. Обращения, которые передал сам AI,
тоже назначаются свободному оператору, но без таймера. Без операторов в списке или с `OPERATOR_FIRST=0`
(по умолчанию) сначала отвечает AI. Настройки: `OPERATOR_WAIT_SECONDS`, `OPERATOR_MAX_SESSIONS`
(разговоров у оператора одновременно, по умолчанию 1), `OPERATOR_IDLE_MINUTES` (30).

Под постом эскалации кнопки: тон клиента, «📝 Заметка о клиенте», «✅ Завершить разговор».
`/menu` в чате поддержки (в группе также `/start`) открывает панель: «📋 Кандидаты в базу знаний»
и «⭐ Рейтинг поддержки». Старые текстовые команды операторов (`/candidates`, `/approve`, `/reject`,
`/client`, `/rating`, `/end`) продолжают работать.

## Журнал переписки (сессии)

Все сообщения сохраняются в таблицу `chat_messages` (`ai_support/chatlog.py`) по порядку: сообщения
клиента (текст, расшифровка голоса или пометка «[фото]»), ответы бота, ответы операторов (с id и именем
оператора) и события («Передано специалисту», «Разговор завершил клиент/специалист»). Каждое сообщение
связано с сессией (`conversations` из `feedback.py`, там же оператор, который вёл разговор) и с
эскалацией. Персональные данные маскируются. По этой таблице админ-панель показывает сессии в виде чата.

## Обучение на ответах операторов

Каждая эскалация сохраняется в SQLite (та же `DB_PATH`): вопрос клиента, ответ бота, язык, тема,
причина, последние сообщения диалога, а также все ответы операторов на неё. Номера карт, ПИНФЛ,
телефоны и балансы маскируются до сохранения.

Сам по себе бот не учится. Первый ответ оператора на эскалацию создаёт кандидата в базу знаний, бот
пишет его в чат поддержки с кнопками:

- «✅ Добавить» — добавить ответ в базу знаний как есть;
- «✏️ Исправить» — бот просит ответить на его сообщение исправленным текстом (например, без деталей
  конкретного клиента) и добавляет его;
- «❌ Отклонить» — не добавлять.

Список непроверенных кандидатов — кнопка «📋 Кандидаты в базу знаний» в панели (`/menu`).

Одобренный ответ попадает в промпт сразу, без перезапуска, и бот использует его на похожих вопросах.
Ответ, который нарушает жёсткие правила (обещанный возврат или срок, подтверждённый успех операции,
разблокировка, изменение лимита, критерии Antifraud), одобрить нельзя: нужно прислать исправленный
текст. Такие ответы не попадают в промпт, даже если оказались в базе. Ответы оператора конкретному
клиенту часто касаются только его случая, поэтому перед одобрением проверяйте, подходит ли ответ всем.

## Оценки и рейтинг

**Клиент оценивает поддержку после завершения разговора.** Ответ бота или передача оператору
открывает разговор. Его завершает клиент кнопкой «✅ Suhbatni yakunlash» в главном меню, либо сотрудник
кнопкой «✅ Завершить разговор» (в диалоге админ-бота или под постом эскалации), либо бот
сам, если в разговоре `SESSION_IDLE_MINUTES` минут (по умолчанию 30, `0` выключает) никто не писал. Только после этого клиент один раз
оценивает разговор: бота, если разговор не дошёл до человека, иначе оператора (1⭐–5⭐, «Не ответили»,
«Не смогли помочь»; «Не ответили» есть только для оператора). Оценку можно изменить. «Не ответили» и
«Не смогли помочь» считаются как 1⭐. При низкой оценке бота клиенту подсказывают кнопку «Оператор»;
бот ничего не обещает. Следующий вопрос после завершения начинается без старого контекста.

**Поддержка оценивает клиента.** В посте эскалации есть AI-оценка клиента по истории чата (суть
проблемы, предложения клиента, тон: вежливо / спокойно / грубо) и уровень клиента. Оператор ставит
свою оценку тона кнопками под постом и пишет заметку кнопкой «📝 Заметка о клиенте»
(`суть проблемы | предложения`). Когда разговор закрыт (клиентом, оператором или по тишине), AI
оценивает клиента по всему разговору, а если его вёл оператор, бот отвечает на пост эскалации
сообщением «🏁 Разговор завершён… Оцените клиента» с той же AI-оценкой, кнопками тона и заметки.
Оценка оператора важнее AI-оценки того же обращения.

**Уровни клиентов** (по тону в обращениях): A · вежливый (2+ обращения, без грубости, в основном
вежливо), C · требует внимания (грубость дважды или в трети обращений), B · обычный (остальные),
«новый» — оценок ещё нет.

**Анонимный рейтинг:** кнопка «⭐ Рейтинг поддержки» в панели (`/menu`) в чате поддержки показывает средний балл и распределение 5★…1★, как
в магазине приложений, отдельно по AI-боту и операторам, баллы операторов и анонимную сводку по
уровням и тону клиентов. Идентификаторов клиентов в рейтинге нет.

Оценки и уровни только внутренние: клиенту их не показывают, и бот не меняет из-за них ответы,
лимиты или доступ.

## Админ-бот и веб-панель

Отдельный Telegram-бот для администраторов (`python -m ai_support.admin`, в Docker Compose сервис `admin`)
с веб-панелью внутри Telegram (mini app). Панель публикуется через Cloudflare Tunnel (сервис `tunnel`),
открывать порты на сервере не нужно.

- **Сессии как чаты.** Клиентский бот сохраняет каждое сообщение (`chatlog.py`): что написал клиент
  (голос — расшифровкой, фото — с подписью), что ответил бот, что ответил оператор, и события («передано
  оператору», «клиент завершил разговор», оценка). Сессия — это один разговор от первого вопроса до
  завершения. В панели видно, какой оператор вёл сессию, статус, тему и оценку; открытая сессия
  обновляется сама. Номера карт, ПИНФЛ, телефоны в тексте и балансы маскируются до сохранения.
  Сессии, начатые до этой версии, собираются из сохранённой эскалации и ответов оператора.
  Чат выглядит как в Telegram: обои, пузырьки, даты, служебные сообщения. Фото, голосовые и файлы
  клиента открываются прямо в чате: в базе хранится только их Telegram file_id, а панель скачивает файл
  у Telegram токеном клиентского бота (`TELEGRAM_BOT_TOKEN` из того же `.env`) в момент просмотра.
  Сообщения, сохранённые до этой версии, показываются подписью «📷 Фото» без картинки.
- **Операторы.** Операторов может быть сколько угодно. Администратор добавляет оператора по номеру
  телефона: в боте «➕ Добавить оператора» → `+998901234567 Имя` (или поделиться его контактом), либо в
  панели. Потом оператор открывает клиентский бот, нажимает /start и при регистрации делится этим номером:
  бот привязывает его Telegram id и пишет, что он подключён как оператор. Если человек уже зарегистрирован
  в боте с этим номером, он становится оператором сразу. Можно добавить и по Telegram id (`123456789 Имя`
  или пересланное сообщение). Администратор может отключить оператора. Пока нет ни одного привязанного
  активного оператора, клиентам отвечает любой участник чата поддержки, как раньше. Потом ответы в чате
  поддержки доходят до клиента только от активных операторов из списка и от админов из `ADMIN_IDS`,
  остальным бот пишет, что их нет в списке, и называет их Telegram id, чтобы админ мог добавить их по id.
  Оператор, добавленный по номеру и ещё не зарегистрированный, помечен «ждём регистрации». Номер можно
  писать в любом виде: `+998 90 123 45 67`, `998901234567`, `90 123 45 67`, `901234567` (без кода страны
  добавляется 998; девять цифр, совпадающие с id уже зарегистрированного клиента, считаются Telegram id).
  Контакт, отправленный в админ-бот, привязывает оператора сразу: в нём уже есть Telegram id.
  В панели оператора можно изменить (имя, телефон) и удалить; его прошлые ответы и сессии остаются в истории.
- **Поддержка в админ-боте.** Меню «🎧 Поддержка» (и команда `/support`) — список клиентов, которые ждут
  человека или которым уже отвечает сотрудник: сначала ждущие, у остальных видно, кто ведёт. Нажатие на
  клиента показывает последние сообщения переписки и открывает диалог: всё, что сотрудник пишет в
  админ-бот (текст или фото), клиент получает от клиентского бота обычным сообщением, без подписи и
  кнопок, как от живого сотрудника. Под диалогом «✅ Завершить разговор» (клиента просят оценить) и
  «⬅️ К списку клиентов». Пользоваться меню могут админы из `ADMIN_IDS` и активные операторы; операторы
  видят только его. Когда AI передаёт клиента человеку, клиентский бот сообщает об этом через админ-бот
  (`ADMIN_BOT_TOKEN`) с кнопкой «💬 Открыть диалог»: назначенному оператору, иначе всем активным
  операторам, иначе админам. Туда же приходят новые сообщения клиента (с фото, голосовыми и файлами) —
  тому, кто ведёт разговор. Сотрудникам не нужно писать в клиентский бот, поэтому их переписка не
  нагружает его и не упирается в лимиты Telegram. Если оператора добавили по номеру, он открывает
  админ-бот и делится номером кнопкой «📱 Я оператор: поделиться номером». Оператор должен хотя бы раз
  открыть админ-бот (`/start`), иначе Telegram не даст боту написать ему первым; тогда уведомление
  получают админы. Чат поддержки (`SUPPORT_CHAT_ID`) по-прежнему работает, если он задан.
- **Ответ из панели.** Внизу чата сессии есть поле ответа. Клиент получает его обычным сообщением, как
  ответ оператора; сообщение сохраняется в сессии от имени админа, и AI больше не забирает этот разговор.
  Если задан чат поддержки, копия уходит туда реплаем к посту эскалации. Если сессию вёл только бот,
  открывается передача человеку, и следующие сообщения клиента приходят в админ-бот (и в чат поддержки,
  если он есть). Ответ на завершённую сессию открывает клиенту новый разговор. Отправка идёт токеном
  клиентского бота (`TELEGRAM_BOT_TOKEN`).
- **Быстрые вопросы.** Вкладка «Вопросы» показывает меню клиентского бота по темам. У каждого вопроса
  можно написать инструкцию на каждом языке: текст ответа, шаги решения по порядку и до 10 скриншотов
  (PNG или JPEG до 5 МБ, общие для всех языков). Если у вопроса есть инструкция на языке клиента, бот
  сразу отправляет её (текст и шаги, затем скриншоты одним альбомом) без AI и без ожидания оператора;
  без инструкции вопрос, как раньше, уходит AI по базе знаний. Можно переименовать или скрыть встроенный
  вопрос и добавить свой вопрос в тему; у своего вопроса на языке без текста клиент видит русский
  (или другой заполненный) вариант. Перед сохранением весь текст проверяется теми же правилами, что и
  ответы бота (`ai_support/guardrails.py`): обещание возврата или срока, подтверждение платежа,
  разблокировка и правила антифрода не сохраняются, панель показывает, какая фраза и где не прошла.
  Инструкции и скриншоты хранятся в той же базе (`ai_support/guides.py`); Telegram file_id фото бот
  запоминает после первой отправки.
- **Активность.** Сводка (клиенты, открытые сессии, ждут оператора, сообщения за день, рейтинги),
  по каждому оператору — ответы, сессии, открытые сессии, последний ответ и средняя оценка, список
  клиентов с поиском (по имени, @username, id и телефону, если регистрация его сохранила) и все сессии клиента.

Полный доступ только у пользователей из `ADMIN_IDS`, операторам доступно меню «Поддержка»; остальным бот
отвечает их Telegram id. Панель проверяет
подпись Telegram (initData) токеном админ-бота на каждом запросе.

Настройка:

1. Создайте второго бота в @BotFather (не клиентского) и впишите токен в `ADMIN_BOT_TOKEN`.
2. Напишите админ-боту: он ответит вашим Telegram id. Впишите id администраторов в `ADMIN_IDS` через запятую.
3. В Cloudflare Zero Trust → Networks → Tunnels создайте туннель, скопируйте его токен в
   `CLOUDFLARE_TUNNEL_TOKEN`. Во вкладке Public Hostname добавьте домен (например `admin.example.com`)
   с сервисом `http://admin:8080` и впишите этот домен в `ADMIN_DOMAIN`.
4. `docker compose up -d --build` — запустятся `bot`, `admin` и `tunnel`. В админ-боте появится кнопка
   «🖥 Открыть панель».

**Если по домену Cloudflare показывает Error 1033**, к туннелю не подключён ни один `cloudflared`:
проверьте `docker compose ps` (контейнер `xonsaroy-ai-support-tunnel` должен быть `Up`, не `Restarting`) и
`docker compose logs --tail=50 tunnel`. В `CLOUDFLARE_TUNNEL_TOKEN` должен быть только сам токен (строка на
`eyJ…`) без `cloudflared service install`, кавычек и пробелов, и именно того туннеля, где опубликован домен.
Успешный запуск пишет в лог `Registered tunnel connection`, а туннель в Cloudflare становится Healthy.
Если в логе `failed to dial … 7844`, провайдер закрывает UDP: добавьте в `.env` `TUNNEL_TRANSPORT_PROTOCOL=http2`.

Без `ADMIN_BOT_TOKEN` сервис `admin` сразу завершается и не перезапускается, клиентский бот работает как раньше.

## Чаты в CRM поддержки (только просмотр, по токену)

CRM команды поддержки может показывать чаты AI Support (сессии клиентов с ответами бота и операторов),
не получая доступа к админ-панели. Код: `ai_support/admin/crm.py`, работает внутри сервиса `admin`
по тому же домену `ADMIN_DOMAIN`.

**Безопасность.**
- У каждой CRM свой токен `crm_…`. В базе хранится только его SHA-256 хэш; сам токен показывается один раз.
  Токен можно отозвать (перестаёт работать сразу, вместе со всеми выданными им ссылками), задать срок
  действия и список разрешённых IP-адресов или сетей (адрес берётся из `CF-Connecting-IP` Cloudflare).
  Список IP ограничивает сам токен (то есть сервер CRM); ссылки для iframe открываются из браузеров
  сотрудников, их защищает короткий срок жизни и подпись.
- Только чтение: из CRM нельзя ответить клиенту, изменить оператора или что-то ещё. Токен CRM не
  открывает `/api/` админ-панели, а подпись Telegram администратора не открывает `/crm/v1/`.
- Номера карт, ПИНФЛ, телефоны и балансы в тексте маскируются (как и в журнале); телефон клиента
  показывается как `+*** ** *** ** 67`. Фото, голосовые и файлы клиента отдаются только токену с правом
  `media`, полный телефон — только с правом `pii`.
- Лимит запросов на токен (`CRM_RATE_PER_MINUTE`, по умолчанию 120 в минуту) и на адрес без токена
  (подбор ключей), только HTTPS, ответы с `Cache-Control: no-store`, журнал каждого запроса
  (токен, путь, IP, статус; хранится 90 дней).
- Страницу чатов можно встроить в iframe только с сайтов из `CRM_FRAME_ANCESTORS` (CSP `frame-ancestors`);
  по умолчанию встраивание запрещено.

**Выдать токен** (на сервере):

```bash
docker compose exec admin python -m ai_support.admin.crm create "CRM поддержки" --ips 203.0.113.10 --days 365
docker compose exec admin python -m ai_support.admin.crm list
docker compose exec admin python -m ai_support.admin.crm revoke 1
```

`--scopes media` разрешает фото и голосовые клиентов, `--scopes media,pii` ещё и полный телефон.
То же доступно администраторам через API панели: `GET/POST /api/crm/tokens`, `DELETE /api/crm/tokens/{id}`,
`GET /api/crm/tokens/{id}/audit`.

**Способ 1: API** (CRM забирает чаты своим сервером, токен в заголовке `Authorization: Bearer crm_…`):

| Запрос | Что возвращает |
|---|---|
| `GET /crm/v1/sessions?status=open&client=<id>&since_id=<id>&limit=50` | список сессий (новые сверху) |
| `GET /crm/v1/sessions/{id}` | сессия с сообщениями (`sender`: client, bot, operator, system) |
| `GET /crm/v1/media/{message}/{n}` | фото, голосовое или файл клиента (право `media`) |
| `GET /crm/v1/me` | имя токена и права |

**Способ 2: встроить страницу.** Сервер CRM просит ссылку на 1 час (до 8 часов), можно для одной сессии
или одного клиента, и показывает её в iframe:

```bash
curl -X POST https://ADMIN_DOMAIN/crm/v1/embed-links -H "Authorization: Bearer crm_…" \
     -H "Content-Type: application/json" -d '{"session_id": 125, "minutes": 60}'
# {"url": "https://ADMIN_DOMAIN/crm/#key=crmt_…", "expires_at": "…"}
```

Ключ ссылки стоит после `#`: браузер не отправляет эту часть на сервер и в Referer, а страница сразу
убирает его из адресной строки. Сам токен в браузер не попадает. Если CRM умеет встроить только постоянный
адрес, можно открыть `https://ADMIN_DOMAIN/crm/#key=crm_…` с токеном; тогда обязательно ограничьте его по IP
сотрудников и сроку.

В `.env`: `CRM_FRAME_ANCESTORS=https://crm.example.uz` (адрес CRM), при необходимости `CRM_RATE_PER_MINUTE`
и `CRM_TRUST_PROXY=0`, если перед панелью не Cloudflare.
